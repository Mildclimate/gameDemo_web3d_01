## 优化：重复物体合并为 InstancedMesh

### 改动前的一批重复物体

| 物体     | 共享几何体 | 共享材质         | 优化前 Mesh 数 | 优化后             |
| -------- | ---------- | ---------------- | -------------- | ------------------ |
| 边界墙   | `unitBox`  | `stone`          | 16             | 1 个 InstancedMesh |
| 墙体灯带 | `unitBox`  | `trim`（自发光） | 8              | 1 个 InstancedMesh |
| 地面碎石 | `unitBox`  | `stone`          | 4              | 1 个 InstancedMesh |
| 祭坛立柱 | `unitBox`  | `metal`          | 4              | 1 个 InstancedMesh |
| 柱顶灯帽 | `unitBox`  | `trim`（自发光） | 4              | 1 个 InstancedMesh |
| **合计** |            |                  | **36**         | **5**              |

### 实测对比

| 指标       | 优化前 | 优化后  | 变化              |
| ---------- | ------ | ------- | ----------------- |
| Draw Calls | 239    | **148** | **−91（−38.1%）** |
| Triangles  | 11,276 | 11,672  | +396（+3.5%）     |
| Geometries | 26     | 26      | 不变              |
| Textures   | 7      | 7       | 不变              |

测量方式：同一台机器、同一浏览器会话、同一画质档位，仅切换提交前后的代码，各读取一次面板稳定值。

### 结果分析

- **Draw Calls 下降 91 次**，高于按「36 个 Mesh → 5 个 InstancedMesh」估算的 72 次（每帧 1 次主渲染 + 1 次阴影渲染）。差额未进一步拆解，可能与阴影通道的逐个剔除差异有关。
- **Triangles 增加 396**：InstancedMesh 以整组包围球做视锥剔除，即使只有部分实例在视野内，整组仍会提交全部实例，因此比逐个 Mesh 剔除时多绘制约 33 个盒体（33 × 12 = 396）。相对 1.1 万面的总量可以忽略。
- **Geometries / Textures 无变化**：本来就在复用 `unitBox` 与少量材质，实例化后仍复用同一份几何体。

## 无法可靠采集的指标

| 指标          | 原因                                                                                                                                                    |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FPS           | 自动化浏览器中 `requestAnimationFrame` 被节流，面板 FPS 读数为 0，不代表真实帧率。**因此本文档不记录 FPS 数值**，需在真实设备手动游玩时观察右上角面板。 |
| 内存 / 堆占用 | 未接入 `performance.memory` 采样，未测量。                                                                                                              |
| 加载耗时      | 当前场景无外部模型与纹理，只有代码体积，未单独测量。                                                                                                    |
| 移动端表现    | 尚未在真机（iOS / Android）测试，仅有窄屏布局验证。                                                                                                     |

## 未做的优化

- 边界墙组与祭坛立柱组在遮挡时**整组淡出**（见下方限制），因此没有进一步拆分为更多 InstancedMesh。
- 未做代码分割，Three.js 仍与业务代码打进同一个 chunk（约 656 kB）。
- 未引入 Draco / KTX2：场景尚无外部资产。

## 已知限制

- **遮挡淡出的粒度变粗**：合并前，摄像机与角色之间被挡住的那一段墙单独变透明；合并后整圈墙与灯带共享同一份材质，只能整组淡出。实测该情况只在角色紧贴墙边时触发，且墙与灯带同时变透明，不会出现灯带悬空的割裂感。
- 上表数据来自开发服务器，生产构建未单独复测 Draw Calls（逻辑相同，理论一致）。

## 复现步骤

1. `npm install`
2. `npm run dev`，打开控制台输出的本地地址
3. 点击「开始探索」，静止约 3 秒
4. 读取右上角性能面板的 Draw Calls / Triangles / Geometries / Textures
5. 需要对比时，切换到优化前的提交并重复上述步骤（保持同一浏览器与画质档位）
